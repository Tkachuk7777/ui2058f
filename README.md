# UI2058F / UI2088F — Калькулятор калибровки

**Метрологическая калибровка и валидация измерительных каналов испытательной установки**

Десктопное приложение (**Python + Tkinter**) для калибровки и валидации измерительных каналов установки **UI2058F / UI2088F**. Подключается к прибору по TCP, считывает пакеты телеметрии и осциллограммы, считает калибровочные коэффициенты методом наименьших квадратов, проверяет остаточную погрешность и формирует протокол в Excel.

> [!WARNING]
> Протокол опроса прибора восстановлен **реверс-инжинирингом**. Официальная документация производителя не использовалась. Структура пакетов и смещения полей определены экспериментально — при смене прошивки прибора они могут потребовать уточнения.

## Что за прибор

**UI2058F / UI2088F** — испытательная установка для LED-драйверов и светодиодных светильников. Одновременно измеряет:

| Канал | Что измеряется |
|-------|----------------|
| **Вход (AC сеть)** | U_RMS, I_RMS, активная мощность, коэффициент мощности, частота |
| **Выход CV** | V_Lamp, I_Lamp, Pout, КПД (стабилизация напряжения) |
| **Выход CC** | I_Lamp, V_Lamp, Pout, КПД (стабилизация тока) |
| **Осциллограммы** | Напряжение и ток, ~256 точек на период → THD и гармоники до 40-й |

Прибор отдаёт «сырые» значения. Для соответствия эталону (**Agilent 34401A**) их нужно пересчитывать по индивидуальным коэффициентам `Ref = a·Dev + b`, которые и вычисляет приложение.

## Как подобран протокол опроса

### Транспорт

Прибор доступен через **TCP-serial bridge** (виртуальный COM-порт по сети).

- Адрес по умолчанию: `ххх.ххх.ххх.ххх:4001` — задаётся в UI.
- Без аутентификации, «сырой» поток байт.
- На сокет навешен `TCP_NODELAY`, чтобы команды не слипались с задержкой Нагла.
- Класс `TcpSerial` эмулирует интерфейс `pyserial` (`in_waiting`, `read`, `write`, `flush`) — вся логика чтения писалась так, будто это обычный COM-порт.

### Команды

Все команды — одиночный байт.

| Команда | HEX | Назначение | Таймаут ответа |
|:-------:|:---:|-----------|:--------------:|
| `v` | `0x76` | Handshake / опознание при подключении | 500 мс |
| `?` | `0x3F` | Предварительный запрос перед измерением | 200 мс |
| `2` | `0x32` | Триггер измерения | 200 мс |
| `!` | `0x21` | Запрос фрагмента данных (пакета) | 700 мс × до 20 попыток |

Цикл измерения:

```text
connect → \x76
for попытка in 1..5:
    \x3F → \x32 → пауза 200 мс
    read_packet()          # повторяет \x21, накапливая до 5 чанков / 2000 байт
    попытка распарсить пакет
```

`read_packet` при каждом вызове шлёт `\x21` и в течение 700 мс собирает байты. Накопив ≥ 5 чанков **или** ≥ 2000 байт — прекращает опрос и парсит накопленное.

### Структура пакета телеметрии

Пакет не имеет фиксированной обёртки. Поиск данных — **сканер по смещению**: идём по сырым байтам с шагом 1 и пытаемся интерпретировать 5 подряд идущих `float32` (LE) как кортеж `M = (U, I, P, PF, F)`. Пакет валиден, если все поля попадают в физически осмысленные диапазоны:

| Поле | Диапазон |
|------|----------|
| U_RMS, В | `0.1 < U < 600` |
| I_RMS, А | `0.0001 < I < 50` |
| P, Вт | `-10000 < P < 10000` |
| PF | `-2.0 ≤ PF ≤ 2.0` |
| F, Гц | `10 < F < 100` |

Найдя смещение, приложение дополнительно распаковывает `<15f` с того же оффсета. Используются первые 5, остальные 10 приберегаются для будущих прошивок.

### Осциллограммы

Отдельные чанки ответа содержат **сырые отсчёты int16 little-endian** — по одному периоду сигнала. Для каждого чанка перебираются оффсеты `0..9` (выравнивание):

1. `as_i16` — приведение к массиву `float`.
2. Фильтр `ptp ∈ [50, 10000]` — отсекаем «плоские» и перегруженные сигналы.
3. Фильтр `THD < 80 %` — отбрасываем явно несинусоидальные артефакты.
4. Фильтр `RMS ≥ 20` — отсекаем шум.

Эвристика выбора:

- **Напряжение** — сигнал с **минимальным** THD (форма синуса сети).
- **Ток** — среди оставшихся сигнал с **максимальным** THD (у LED-драйвера ток импульсный, богатый гармониками).
- **Фаза** — ток сдвигается по нулевой точке напряжения, при необходимости пересэмплируется на 256 точек.

Гармоники считаются через `rfft`, амплитуды нормируются как `|X_k|·√2 / N`, THD — как `√(Σ H₂..H₄₀²) / H₁ · 100 %`.

### Дополнительные поля

Экспериментальные смещения — **самая хрупкая часть реверса**:

| Что | Где ищется | Как парсится |
|-----|-----------|--------------|
| V_Lamp (CV) | последний чанк ответа, оффсет 0 | `<f` |
| V_Lamp (CC) | последний чанк ответа, оффсет 0 | `<f` |
| I_Lamp | последний чанк, оффсет 4 | `<f` |
| КПД (Efficiency) | последний чанк, оффсет 16 | `<f` |
| Pout | `chunks[2]`, оффсет 12 | `<h / 100.0` |

> [!IMPORTANT]
> Если у тебя другая ревизия прошивки UI2058F/UI2088F и `V_Lamp` / `I_Lamp` / `Efficiency` читаются неверно — первым делом проверь именно эти оффсеты в функции `measure()`.

## Функционал

### 5 вкладок GUI

| # | Вкладка | Что вводится | Что считывается |
|:-:|---------|--------------|-----------------|
| 1 | **Вход (12 точек)** | U_ref (В), I_ref (мА) — 4 группы мощностей × 3 напряжения (176 / 220 / 264 В) | U_dev, I_dev, P_dev, PF |
| 2 | **Выход CV** | V_Lamp_ref (В), I_Lamp_ref (А) — 4 точки | V_Lamp, I_Lamp, Pout, КПД, V_RMS, I_RMS, PF |
| 3 | **Выход CC** | I_Lamp_ref (А), V_Lamp_ref (В) — 3 точки | I_Lamp, V_Lamp, Pout, КПД, V_RMS, I_RMS, PF |
| 4 | **Валидация** | — | Таблица остаточных погрешностей и «вердиктов» |
| 5 | **Инструкция** | — | Встроенная памятка (дублируется в Excel) |

**Кнопка [R]** на каждой точке:

- Шлёт запрос прибору и асинхронно (в отдельном потоке) читает пакет.
- Заполняет поля `Dev`.
- Пока идёт чтение — жёлтая, при успехе — зелёная (OK), при ошибке — красная (X).
- Считанные поля на 2 секунды подсвечиваются зелёным — видно, куда пришли данные.

### Правая панель «Коэффициенты»

Все 9 пар `(a, b)` пересчитываются в реальном времени при любом изменении полей.

> Если `|a − 1| > 5 %` — коэффициент становится **красным**. Это индикатор аппаратного дефекта (шунт / делитель).

### Excel

**Сохранить в Excel** — книга из 5 листов:

| Лист | Содержимое |
|------|-----------|
| `0. Протокол` | Шапка, метаданные (тип, S/N, эталон Agilent 34401A), 18 коэффициентов, готовые формулы для `Dev_раб → Corr_раб` |
| `1. Вход` | Сырая таблица входных измерений |
| `2. Выход CV` | Сырая таблица CV |
| `3. Выход CC` | Сырая таблица CC |
| `4. Валидация (Годен)` | Только точки, прошедшие допуск |
| `5. Инструкция` | Копия встроенной памятки |

> В листе «Инструкция» строки-разделители `====` намеренно заменяются на `----`, чтобы LibreOffice не интерпретировал их как формулы.

**Загрузить из Excel** — обратное восстановление полей по тем же листам + автоматическое заполнение S/N и типа прибора.

## Методика калибровки

Для каждого канала строится **линейная регрессия** по точкам:

```text
Ref = a · Dev + b
```

| Параметр | Формула |
|----------|---------|
| Средние | `X̄ = mean(Dev), Ȳ = mean(Ref)` |
| Наклон `a` | `Σ (Devᵢ − X̄)(Refᵢ − Ȳ) / Σ (Devᵢ − X̄)²` |
| Смещение `b` | `Ȳ − a·X̄` |

**Тонкости реализации:**

- **Фильтрация нулевых точек** — пары с `Ref = 0` или `Dev = 0` автоматически выкидываются, чтобы «пустые» строки не тянули прямую в ноль. Для расчёта нужно минимум **2 точки** на канал.
- **Независимый расчёт P** — `P_ref` и `P_dev` считаются как `U·I·PF / 1000` (Вт), а не берутся из прибора напрямую. Так коэффициент мощности вносит вклад согласованно.
- **Для CC-режима** — `Pout_ref = U_out · I_ref`, `Pout_dev = U_out_dev · I_dev`.

## Валидация и отбраковка

Проверка в **два уровня**.

### Уровень А — «здоровье железа»

`a` должно попадать в диапазон `0.95 … 1.05`. Выход за пределы — **красный** коэффициент в правой панели. Признак аппаратной проблемы (неверный шунт, делитель), даже если программно прямая «вытягивается».

### Уровень Б — остаточная погрешность

Для каждой точки:

1. `Corr = a · Dev + b`
2. `Δ % = (Corr − Ref) / Ref · 100 %`
3. Сравнение с **комбинированным допуском** (% от показания + абсолютное смещение):

| Величина | Допуск |
|----------|--------|
| Напряжение | ±(1.0 % + 0.25 В) |
| Ток | ±(1.2 % + 1.5 мА) |
| Мощность | ±(1.5 % + 0.5 Вт) |

> **Зачем комбинированная формула?** Защищает от ложного брака на **малых токах**, где ВЧ-пульсации импульсного LED-драйвера дают заметный вклад в абсолютную ошибку.

Итог: точка получает `ГОДЕН` или `БРАК`. Проблемные ячейки на рабочих вкладках подсвечиваются красным фоном (`DevFail.TEntry`). В Excel попадают только «Годен».

## Установка и запуск

```bash
git clone https://github.com/Tkachuk7777/ui2058f.git
cd ui2058f

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install numpy pandas openpyxl pyserial
python ui2058f_gui.py
```

> `pyserial` импортируется на старте (исторически приложение писалось под COM-порт и позже было переведено на TCP). Реально используются `numpy`, `pandas`, `openpyxl`; `pyserial` оставлен «на всякий случай» для обратной совместимости.

### Быстрый старт

1. Подключить прибор по сети, убедиться что `172.16.8.145:4001` пингуется.
2. Ввести IP / порт, нажать **«Подключить»** — загорится зелёное «Подключено».
3. Ввести `Ref`-значения на вкладках 1–3 (или загрузить из Excel).
4. Нажимать **[R]** у нужных точек — приложение само сходит за пакетом и заполнит `Dev`.
5. Смотреть правую панель (коэффициенты) и вкладку **«Валидация»**.
6. **«Сохранить в Excel»** — получить готовый протокол.

## Архитектура

```text
ui2058f_gui.py
├── TOL_*, MAX_GAIN_DEV                       # константы допусков
├── TcpSerial                                 # TCP → эмуляция pyserial
├── drain / cmd                               # примитивы обмена
├── as_i16 / safe_resample                    # осциллограммы
├── find_M / find_M_in_chunks                 # парсер float-пакета
├── collect_signals                           # поиск сигналов U/I по чанкам
├── harmonics                                 # FFT → амплитуды гармоник
├── zero_cross                                # фаза
├── measure                                   # полный цикл одного измерения
├── linreg / calc_input / calc_cv / calc_cc   # МНК
└── class App                                 # GUI: связь, 5 вкладок, Excel I/O
```

**Ключевое архитектурное решение** — изоляция сетевого чтения в фоновом потоке. Клик по **[R]** кладёт задачу в `threading.Thread`, результат складывается в `queue.Queue`, а UI-поток в `root.after(100, check_read_queue)` забирает его и обновляет поля. Это не даёт Tkinter-циклу «залипнуть» на 3-секундных таймаутах сокета.

## Ограничения

- Протокол **не документирован производителем**. Все смещения (особенно `vlamp`, `ilamp`, `eta`, `pout_int`) эмпирические. При смене прошивки их, вероятно, придётся пересматривать.
- Фаза тока вычисляется по нулевой точке напряжения и простому сдвигу — при сильно искажённой форме сигнала фаза может «плавать».
- Функция `phase_ui2058()` присутствует в коде, но в текущей версии **не вызывается** (оставлена на будущее).
- Допуски `1.0 % / 1.2 % / 1.5 %` + аддитивная часть подобраны под паспортную точность установки и **могут быть ужесточены** под конкретную задачу — собраны в константы в начале файла.
- Данные с эталонного мультиметра вводятся **вручную**.
